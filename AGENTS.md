# ಇತಿಹಾಸ (Itihāsa) — handoff for agents

Browsable Sanskrit epics: Vālmīki Rāmāyaṇa (site root), Mahābhārata (`/mbh/`) and the Bhagavadgītā taken out of it (`/gita/`), with Kannada / Devanāgarī / IAST scripts, two editions of each, word-by-word analysis, a built-in dictionary, and an appendix of metres. Static site, built by Python, no server.
Repo `hms-cap/Ramayana` · live (Vercel) https://ramayana-blond.vercel.app/ (the old GitHub Pages copy is no longer updated) · version in `site/static/version.js` (now 0.10.2) · owner: Hemanth.

## How it is built and shipped
- `python site/build.py` (Jinja2 + lxml, `requirements.txt`) reads `data/` and writes `dist/` (~600 MB, 100k+ files, ~5,500 chapter pages). `python site/build.py` takes a few minutes.
- CI (`.github/workflows/tests.yml`): unittest → full build on every push; it no longer deploys.
- Hosting: Vercel project `ramayana` (team hmullur-1572). `vercel.json` installs into a venv (the image's Python is externally managed), builds, publishes `dist/` (~610 MB, ~9.7k files), and via `ignoreCommand` builds only when `site/static/version.js` changes; force a deploy with Redeploy in the dashboard. Each deployment is a full copy, so keep deployment retention short. `SITE` in `build.py` is the address printed on shared cards. A Vercel MCP server is available in some sessions.
- Run locally: `python site/build.py && python -m http.server 8765 --directory dist`.
- Tests: `python -m unittest discover -s tests` (42) and Playwright scripts in `tests/e2e/` (`home swipe chant pwa mbh mbh_words dict chandas gita`; see its README). Run the e2e ones against the local server with `service_workers="block"`.
- **Every release needs** a bump of `site/static/version.js`, a `CHANGELOG.md` entry and a `data/changes.json` entry (a test fails otherwise). Commit trailer: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Layout
- `data/normalized/{ce,vu}.jsonl` (Rāmāyaṇa) and `data/normalized/mbh/{ce,vu}.jsonl` (Mahābhārata): one record per verse `{uid,k,s,v,lines:[[pāda…]],meter,…}` in IAST. `ce` = critical (Baroda / Pune), `vu` = Traditional (Vulgate / Kumbakonam). **The Traditional text is the default shown**; critical is off by default.
- `data/normalized/gita/{ce,vu}.jsonl`: the Gītā, made by `etl/extract_gita.py` from the Mahābhārata files (Pune Bhīṣma 23–40, Kumbakonam 25–42); records `{uid:"BG-VU-02-047", ch, v, speaker, lines, meter, mbh_uid}`. `data/gita/`: `dhyana.json` (9 Dhyāna ślokas, variants and sources), `chapters.json` (18 adhyāya names), the removed GRETIL additions. `data/crosswalk/gita/` Pune↔Kumbakonam for the Gītā (698/700 match). Kumbakonam ch. 13 has the extra verse 13.1 (35 verses); its merged record VU-6-037-026 is split into Gītā 13.26 + 13.27 (`SPLIT` in `extract_gita.py`). **Text corrections:** `data/gita/errata_vu.json` (228 slips in the Kumbakonam Gītā) is applied to `data/normalized/mbh/vu.jsonl` by `etl/apply_errata.py` (idempotent; records get `corrected`); pipeline after any re-ingest of Kumbakonam: `ingest_mbh.py vu <SARIT xml>` → `apply_errata.py` → `extract_gita.py`. After a re-ingest of Pune: `fix_mbh_gita_preface.py` → `fix_pada_markers.py` (or the new ingest, which splits ';' itself) → `extract_gita.py`.
- `data/crosswalk/…` verse alignment between editions (Rāmāyaṇa, and Mahābhārata Pune↔Kumbakonam: 84% of Pune verses match). `data/normalized/mbh/words.jsonl.gz` DCS word analysis (72,711 of 73,821 Pune verses; none for Gītā 6.23–40, 7.173 and ~300 others). `data/lexicon/` glosses.
- `etl/`: one-off pipelines (ingest GRETIL / Wikisource / DCS, `crosswalk.py`, `build_lexicon.py`, `meter.py`, `chandas.py`, `translit.py` with SLP1 pivot, `grammar.py`, `card_art.py` icons, `daily.py`/`mbh_art.py` for home cards, `sync_kosha.sh`). `etl/sources.json` lists every source and licence.
- `site/build.py` (the generator; per-work `WORKS` dict, ram prefix `""`, mbh prefix `mbh/`, gita prefix `gita/` with `single=True`: one unit, pages `gita/<ed>/1/<adhyāya>/`, adhyāya 0 = Dhyāna, refs adhyāya.verse; `load_recs()` maps Gītā records onto k/s/v; `EPICS` limits the Chandas appendix to the two epics), `site/templates/` (`base, home, sarga, edition, kanda, about, my, appendix, chandas, metre, _art, _strip`), `site/static/` (`app.js` reader and word panel, `lean.js` builds Mahābhārata text in the browser, `home.js`, `dict.js`, `read.js`, `style.css`, service worker, `version.js`).
- `vendor/kosha/`: copy of the Śabdārtha Kaustubha dictionary app (VedaAlokana, pinned commit, see `SOURCE.txt`); `build_dict()` copies it to `dist/dict/` and patches it. Refresh with `etl/sync_kosha.sh <VedaAlokana clone>`.

## What exists (v0.9.0)
Reader with three scripts + scansion + chant; two editions per work with edition badges and crosswalk links; Mahābhārata lean pages (IAST in data, other scripts built client-side); word by word (Rāmāyaṇa and Mahābhārata) with English (Apte + ~600 overrides, 94% of tokens) and Kannada glosses (503 lemmas, ~47% of tokens); tap a word → dictionary card, Full entry / more senses go to `dict/kosha/` and Back restores the verse, word panel and card; dictionary follows light/dark; daily home cards (random mix) for both works; search; offline PWA; names, chips and headings follow the script choice (`sx()` in `build.py`, `.sx-*` CSS); Bhagavadgītā section (v0.10.0): both texts, speaker lines above verses, adhyāya names and cards, Dhyāna ślokas, verse of the day, links to and from the Mahābhārata; no word by word. Pariśiṣṭa chip → `appendix/` → Chandas index (`appendix/chandas/` + a page per metre, 15 metres, counts per kāṇḍa/parva, 8 script-aware examples each, all references for rare metres). Labels use Parva (not "parvan").

## Gotchas
- Kannada display: `render()` turns a class nasal before a same-class stop into anusvāra (`anusvara_before_stops`, mirrored in `translit.js`; the "classical pañcama" option, Kannada-only, does the reverse). Pāda lists: Pune lines can now hold two pādas (`[[a, b], …]`, from GRETIL's ';'); code joins pādas with a space.
- Gītā uids are `BG-<ED>-ch-vvv`; `uid_ref()` turns them into (ed, 1, ch, v). The MBH data is the Gītā's source: after changing Bhīṣma 6.23–42, rerun `etl/extract_gita.py` (and `etl/fix_mbh_gita_preface.py` if the MBH file is re-ingested from GRETIL).
- Rāmāyaṇa and Mahābhārata uids collide (`CE-k-sss-vvv`): Rāmāyaṇa words live in `WORDS`; Mahābhārata words are streamed into `MBH_WORDS` / `MBH_WORD_UIDS`.
- Mahābhārata pages are "lean": do not add per-verse markup to the template without a matching `lean.js` change.
- Prefs live in `localStorage "vr-prefs"` (`script`, `theme` "" = light, `off`, `offMbh`, `offGita`, …); last place per work in `vr.last`, `vr.last.mbh`, `vr.last.gita`; `vr.work` is the last work (`ram`, `mbh`, `gita`; never "app"); `sessionStorage "vr.ret"` carries the dictionary return state.
- Installed service workers cache the shell: patch `version.js` when shell files change; the vendored Kosha `version.js` is patched to `…-itihasa.N` for the same reason.
- Do not use `.wbw-list li` selectors broadly (the dictionary card list reuses the markup). Long `sleep` chains are blocked in the sandbox: use `timeout … until` loops.
- The sandbox cannot open the live site; test on a local build (the Vercel MCP tools can read deployments and build logs).

## Known limits and open work
1. **Kannada glosses and Kannada grammar terms are written by Claude and unreviewed** (About page says so). Next: have a Kannada reader review `etl/gloss_kn.json`; then extend to the next ~1,000 frequent words.
2. **Chandas descriptions, gaṇa formulas and names are unchecked** by a Sanskrit-metrics reader. Metre labels come from `meter.identify`: Anuṣṭubh is by 16 syllables per half-verse only (5th–7th syllable rule not checked); ~7,700 Rāmāyaṇa Traditional and ~20k Mahābhārata Traditional verses are "not identified" (mostly one-syllable irregularities). Idea: classify pathyā/vipulā variants, detect Triṣṭubh–Jagatī mixtures.
3. Dictionary: Kosha's first sense is not always the best (e.g. *tapas*); text licence "not stated, shown on the owner's decision"; Kosha keeps its own teal palette, only light/dark is shared. Possible: choose the sense by context/lemma POS.
4. No word analysis for the Gītā and Droṇa 173; no Kannada for ~half of tokens. Gītā anvaya (prose order) was planned and deferred by the owner: no open licensed source; plan was Claude-drafted pada-ccheda + anvaya as index orderings, auto-checked, marked unreviewed.
8. Gītā text corrections were proofread by Claude only (Sonnet agents, Opus check); a Sanskrit reader should review `data/gita/errata_vu.json` (with its `not_applied` list). The same slip patterns (stray "ka", n/r, `- -` line joins, vakra) exist across the rest of the Kumbakonam Mahābhārata, which has not been proofread; source annotations (`*` lacunae, `(sic)`, `[ ]`, stray verse numbers, ॐ) remain in a few hundred lines of both Traditional texts.
7. Gītā Dhyāna readings were chosen by majority of web witnesses (`data/gita/dhyana.json` variants); a reader should confirm them. The MBH cross-walk `report.json` was not regenerated after the 6.23.1 / 6.40.78 fix (four entries hand-set to match).
5. Mahābhārata Pune text: permission from BORI not checked. Licences are in `etl/sources.json` and the About page.
6. Possible appendix sections beyond Chandas (alaṅkāra, glossary, name index), Back behaviour that skips in-dictionary steps, shrinking the build (compact word files with one shared gloss file, ~152 → ~40 MB; pages drawn in the browser from chapter JSON, ~378 → ~60 MB).
