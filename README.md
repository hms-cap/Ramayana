# ವಾಲ್ಮೀಕಿ ರಾಮಾಯಣ — Vālmīki Rāmāyaṇa reader

A static, browsable edition of the Vālmīki Rāmāyaṇa in Sanskrit, readable in
Kannada script, Devanāgarī and IAST, with cross-script search.

## What's in it

- **Baroda Critical Edition**: 7 kāṇḍas, 606 sargas, 18,761 verses, from GRETIL.
- **Traditional Vulgate**: 645 sargas, 23,386 verses, from Sanskrit Wikisource (via Ramayana_Book).
- **Verse cross-walk** between the two: every verse links to its counterpart, with
  badges for verses that are absent, regrouped or only partly shared, and a switch
  to hide verses not in the other edition.
- One page per sarga; each verse pre-rendered in Kannada script, Devanāgarī and IAST.
- Script modes: Kannada, Devanāgarī, IAST, Kannada + Devanāgarī side by side, or all three.
- Optional "classical pañcama" for Kannada (ಪುಙ್ಗವ instead of ಪುಂಗವ), pārāyaṇa-style; Kannada only.
- Metre identification and laghu/guru scansion for every verse.
- Search in any script or plain English letters (ಮಾರೀಚ, मारीच, mārīca, maricha all match).
- Per-verse permalinks and copyable citations with GRETIL identifiers.
- No server, no build-time network access: the site is plain HTML, CSS and a little JavaScript.

## Layout

```
etl/            source ingestion, transliteration, metre (Python)
  translit.py   IAST / Devanāgarī / Kannada <-> SLP1, search keys
  meter.py      laghu/guru scansion and metre names
  ingest_gretil.py      Critical Edition (TEI-XML)
  ingest_vulgate.py     Vulgate (JSON), with logged mechanical repairs
  crosswalk.py          verse and sarga alignment between the editions
  sources.json  pinned upstream commits and licences
data/           generated, normalized text (see data/README.md)
site/           static site generator (Jinja2), templates and assets
  static/translit.js   browser mirror of translit.py (kept identical by tests)
tests/
```

## Build and run locally

```sh
pip install -r requirements.txt
python -m unittest discover -s tests     # includes a Python/JS parity test (needs node)
python site/build.py                      # writes dist/
python -m http.server -d dist 8000
```

To regenerate the normalized text from upstream:

```sh
etl/fetch_sources.sh
python etl/ingest_gretil.py sources/gretil/gretil.sub.uni-goettingen.de/gretil/corpustei/sa_rAmAyaNa.xml
python etl/ingest_vulgate.py sources/ramayana_book/san
python etl/crosswalk.py
```

## Deployment

The site is hosted on Vercel: https://ramayana-blond.vercel.app/ . `vercel.json` installs
the requirements into a virtualenv, runs `site/build.py` and publishes `dist/`. Vercel builds
only when `site/static/version.js` changes (`ignoreCommand`), so a release (version bump)
deploys and other commits do not; use **Redeploy** in the Vercel dashboard to force one.
Keep few old deployments (Settings → Deployment Retention), since each is a full copy of the
~600 MB site. `.github/workflows/tests.yml` runs the tests and a full build on every push.

## App features (0.4)

Chant view, print / PDF, verse of the day, My list and offline use follow the
*Chant View* and *Home, Versioning, Navigation* design specs. The site stays a
set of static pages (not a hash-route SPA), so the specs' history rules are
implemented with real page navigation; see `site/static/chant.js`.
Daily cards are generated by `etl/daily.py`; hand-written notes go in
`data/daily/curated.json`. Release steps: `CHANGELOG.md`.

## Word-by-word data (phase 3)

    python etl/ingest_dcs.py sources/dcs/ramayanam.txt          # -> data/normalized/words.jsonl
    python etl/build_lexicon.py sources/apte/.../apte-1890.babylon  # -> data/lexicon/gloss.json

Glosses are lemma-level dictionary senses, not translations of the word in
context. `etl/gloss_overrides.json` holds hand-written glosses that take
priority over the dictionary. Grammar labels (Kannada/English) live in
`etl/grammar.py`; the Kannada terms are awaiting review by a grammarian.
